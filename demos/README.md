# Demos

Generated artefacts that show the thing working. Not code, not documentation —
the actual output, kept so it can be looked at later.

A demo is the answer to "does this work?" that does not require running
anything. If someone asks what this project does, a file in here should settle
it.

## Rules

- **Real data only.** Never a mock-up, never a hand-edited sample. A demo that
  was tidied up by hand is a lie about the pipeline.
- **Dated filenames**, newest alongside oldest: `YYYY-MM-DD-<what>.md`.
- **Committed, not gitignored.** The history of demos is how we see whether the
  output got better.
- **Keep the bad ones.** A demo that reads badly is the most useful file here.
