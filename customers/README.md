# Customers

One file per person this is built for. Right now that is one file.

A customer file is not a persona. It is what we actually know about a real
reader: what they train, what data their device produces, what they want out of
this, and what would make them stop using it. Write only what is observed or
what they told you — no invented demographics.

Read the relevant customer file before designing anything that produces output a
human reads. The weekly review is written for a specific person, not a user.

## Adding a friend later

Not yet — see the Later column in ROADMAP.md. When it happens, a new customer
file comes first, and it has to answer: whose Garmin account, whose tokens,
where their data lives, and who sees it. Do not add a real person's data to this
repo without asking first.

## Template

```
# <name or handle>

**Who** — one honest paragraph.
**Trains** — what they actually do, from the data, not from what they say.
**Device and data** — watch, which metrics it populates, history depth.
**Wants** — what would make this worth opening on a Monday.
**Would stop using it if** — the failure modes that lose them.
**Open questions** — what we have not asked yet.
```
